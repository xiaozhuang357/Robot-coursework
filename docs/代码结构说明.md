# LineGuard 源代码结构与运行说明

作者：张立烁；学号：2024303524。对应课程论文《LineGuard 常驻式巡检机器人的软件设计》V2.0。

本项目是一套可运行的巡检任务仿真平台。机器人、相机与驻留站点的动作由后端模拟，浏览器三维画面用于展示。没有使用实机采集数据，也没有训练缺陷识别模型。

以上 Java 文件名在树中省略 `.java` 后缀。`DeviceGateway` 只有 `startOrResume`、`stop`、`stopAll`，目前是调度边界，不是可直接替换真机的完整通信接口。真实接入还需新增指令下发、回执、遥测接收、任务对账与超时机制。

## 2 一次任务如何贯穿架构

1. `MissionConsole` 通过 `api.createTask` 提交检测点，`TaskController` 校验请求后交由业务服务创建 `CREATED` 任务。
2. `dispatch` 事务检查在线、驻留、充电锁止、电量、有效期及设备占用，失败停在 `PRECHECK_FAILED`，成功进入 `DEPARTING`。
3. `MissionApplicationService` 通过网关启动 `SimulationEngine`，后者定时调用 `advanceSimulation`。
4. `MissionStateService` 根据状态推进位置与检测。每次合法转换写入任务与 `TaskEvent`，检测图路径写入 `DetectionRecord`。
5. `RealtimeEventService` 推送变化；前端刷新对应数据。进入 `AWAITING_REVIEW` 后调度停止，等待人工复核。
6. 复核写入 `ReviewRecord` 并进入返航，调度恢复。对接成功后 Robot 归零、补能并清除活动任务；任务进入 `COMPLETED`。

SSE 传递设备快照与任务事件。设备和遥测消息直接更新界面；非遥测事件额外回源查询检测及复核结果，解析失败也触发查询。当前没有断线事件重放。前端收到重新连接事件后主动补拉任务列表、活动任务、资产与设备快照。事件表提供过程留痕，但系统不是通过重放事件来构建所有状态的完整事件溯源架构。

## 3 数据实体与一致性边界

| 实体 | 主要字段与关系 |
|---|---|
| `LineSegment` | 区段编号、名称、长度、说明 |
| `InspectionPoint` | 检测点编号、区段编号、里程、默认检测项 |
| `InspectionTask` | 任务号、来源、检测点、检测项、状态、有效期、创建/更新/完成时间 |
| `Device` | Robot 或 Dock、在线、状态、电量、里程、活动任务号 |
| `DetectionRecord` | 任务、检测点、位置、图像文件名、可判读性、采集序号、时间 |
| `ReviewRecord` | 任务号、人工结论、备注、填写人、时间 |
| `TaskEvent` | 任务号、前状态、后状态、事件类型、说明、时间 |
| `CommandReceipt` | 任务号、指令号、指令类型；任务号与指令号联合唯一 |

表之间通过编号形成应用层逻辑引用，目前没有数据库外键。`@Transactional` 保证单次业务中的数据库写入一起提交或回滚；内存故障标记和图像文件不是数据库事务的一部分。持久化库用于保存当前状态、结果和历史，重启时主动收敛执行状态，避免继续展示已失效的动作。

`COMPLETED` 表示返回对接闭环完成。若提前召回，可能没有检测图或复核记录，因此检测成功应进一步核查可判读图像和复核结果。复核填写人是演示文字，不是经过身份认证的用户。

字段清单与 `domain/*.java` 一一对应（含内部主键与版本号）：

- `LineSegment`：`String id`、`String name`、`double lengthMeters`、`String description`。
- `InspectionPoint`：`String id`、`String lineSegmentId`、`String name`、`double positionMeters`、`String defaultInspectionItem`。
- `InspectionTask`：`UUID id`、`String taskCode`、`TaskSource source`、`String inspectionPointId`、`String inspectionItem`、`TaskStatus status`、`Instant expiresAt`、`Instant createdAt`、`Instant updatedAt`、`Instant startedAt`、`Instant completedAt`、`String statusMessage`、`long version`。
- `Device`：`String id`、`String name`、`DeviceType type`、`String state`、`boolean online`、`int batteryPercent`、`double positionMeters`、`UUID activeTaskId`、`String statusMessage`、`Instant updatedAt`、`long version`。
- `DetectionRecord`：`UUID id`、`UUID taskId`、`String inspectionPointId`、`double positionMeters`、`String imageFileName`、`DetectionQuality quality`、`int captureIndex`、`Instant capturedAt`。
- `ReviewRecord`：`UUID id`、`UUID taskId`、`ReviewConclusion conclusion`、`String remark`、`String reviewer`、`Instant reviewedAt`。
- `TaskEvent`：`Long id`、`UUID taskId`、`TaskStatus fromStatus`、`TaskStatus toStatus`、`String eventType`、`String message`、`Instant createdAt`。
- `CommandReceipt`：`Long id`、`UUID taskId`、`String commandId`、`CommandType commandType`、`Instant receivedAt`。

## 4 HTTP 接口与请求示例

接口前缀为 `/api/v1`。正常创建返回 `201`，查询与操作返回 `200`，没有活动任务返回 `204`；非法业务状态返回 `409`，输入不合法返回 `400`。

| 方法与路径 | 用途 |
|---|---|
| `GET /assets/segments` | 获取区段及候选检测点 |
| `GET /devices` | 获取两类设备状态 |
| `GET /tasks`、`GET /tasks/{id}` | 列表及包含检测、复核、事件的详情 |
| `GET /tasks/active` | 查询活动任务 |
| `POST /tasks` | 创建任务 |
| `POST /tasks/{id}/dispatch` | 预检与派发 |
| `POST /tasks/{id}/review` | 保存复核并返航 |
| `POST /tasks/{id}/actions/recapture` | 不可判读图像限一次重采 |
| `POST /tasks/{id}/actions/return` | 联锁检查后返航 |
| `POST /tasks/{id}/actions/abort` | 站内结束；线上安全驻停 |
| `GET /events/stream` | SSE 通知 |
| `POST /simulator/faults` | 注入或解除仿真故障 |
| `POST /simulator/reset` | 清空本演示实例的任务与图像 |

创建任务：

```json
{"source":"MANUAL","inspectionPointId":"LG-POINT-350","inspectionItem":"连接金具外观检查"}
```

派发任务（把返回的任务 `id` 放入 URL）：

```json
{"commandId":"demo-dispatch-001"}
```

复核：

```json
{"commandId":"demo-review-001","conclusion":"NO_ABNORMALITY","remark":"演示图像可判读","reviewer":"演示运维员"}
```

同一指令重试应使用相同 `commandId`，不同操作使用新编号。现有测试验证串行重复处理；`synchronized` 不等于分布式锁，也不保证跨实例的恰好执行一次。

## 5 本地运行

推荐 JDK 21、Maven 3.9、Node.js 22 或 24，首次构建需联网获取 Maven/npm 依赖。macOS/Linux 启停脚本还使用 Bash、curl、lsof 和 Python 3。先执行 `java -version`、`mvn -version`、`node --version`，确认 Maven 使用 JDK 21。

在提交包根目录执行：

```bash
bash lineguard-system/start-demo.sh
# 浏览器进入 http://localhost:5173
bash lineguard-system/stop-demo.sh
```

Windows PowerShell：

```powershell
.\lineguard-system\start-demo.ps1
.\lineguard-system\stop-demo.ps1
```

也可手动分两个终端启动。终端一：

```bash
cd lineguard-system/backend
mvn spring-boot:run
```

终端二：

```bash
cd lineguard-system/frontend
npm ci
npm run dev
```

后端默认 `8080`，前端默认 `5173`。如端口被占用，先停止自己启动的旧演示进程；不要关闭不属于本项目的服务。演示数据位于 `backend/runtime-data`，停止服务后仍保留。

需要独立测试实例时，前端可设置 `LINEGUARD_API_URL` 指向其他后端；后端的 `lineguard.web.allowed-origins` 也必须包含该前端地址。验证工具使用 `18080/15173` 和独立内存库，不会重置日常演示数据库。

## 6 三分钟演示

1. 进入任务控制台，观察 Robot 已驻留、Dock 已锁止充电，选择检测点 A 并创建任务。
2. 观察离站、移动、检测和上传。切换三维场景与二维工程视图，说明位置和任务状态同步。
3. 查看合成图像，选择复核结论并提交，观察返航和对接完成；在历史页打开事件详情。
4. 新建任务，展开“故障演示”，在移动中注入障碍，观察驻停；此时再注入低电量，机器人仍不能绕过障碍返航。解除障碍后召回。
5. 可追加模糊图演示：派发后、到点前设置模糊图，等待不可判读提示，重采一次后复核。

默认仿真每 700 ms 推进 120 m，是方便演示的时间压缩，不是实际速度。对接直接将电量恢复到 100%，不模拟真实充电时间。实时页面不能代替设备上的独立急停与安全控制。

## 8 模型与文档维护

用 Blender 打开 `model/LineGuard.blend` 可以旋转查看或编辑，`LineGuard.glb` 可导入支持 glTF 的建模工具。模型单位为米，尺寸源文件是 `tools/blender/lineguard_dimensions.py`。它是概念结构展示，不含强度分析或传感器仿真。

论文正文以根目录 `LineGuard_课程论文_V2.0.md` 为源文件，`tools/build_paper.py` 填入教师封面、抽取真实 Java 片段并生成 Word。依赖 `python-docx`。`tools/build_course_figures.py` 使用 Pillow 与中文字体生成架构配图。`tools/verify_paper.py --pdf <实际导出的 PDF>` 校验格式与真实页数，依赖 `python-docx` 和 `pypdf`。排版之后必须检查导出 PDF，不以估算页数作为提交依据。
